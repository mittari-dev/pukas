# Painel `/admin` e conteúdo no Supabase — Plano de Implementação

> **Para agentes:** superpowers:executing-plans (nativo) ou superpowers:subagent-driven-development. Os passos usam checkbox (`- [ ]`).

**Objetivo:** todo o conteúdo do PUKAS passa a morar no Supabase e é publicado por um painel `/admin` com 2FA, sem quebrar nenhum endereço atual.

**Arquitetura:**
- O banco (Postgres no Supabase) é a autoridade das regras: RLS, travas editoriais e histórico vivem em migrações SQL em `supabase/migrations/`.
- O site Astro passa a `output: 'server'` no Vercel. As views atuais continuam, mas recebem dados do banco por `src/lib/banco/`, mapeados para os tipos `Edicao` e `Obra` que já existem.
- Páginas públicas vão para o cache da borda com etiquetas. Publicar invalida as etiquetas.
- O painel é feito de páginas Astro com formulários (POST) e quase nenhum JavaScript.
- A tradução vai em lote para a API do Claude, e um workflow do GitHub recolhe o resultado.

**Stack:** Astro 7 + `@astrojs/vercel`, `@supabase/supabase-js` + `@supabase/ssr`, Supabase CLI (Docker local), `@anthropic-ai/sdk` (Message Batches), Vitest.

**Spec:** [`docs/specs/2026-11-06-painel-design.md`](../specs/2026-11-06-painel-design.md)

## Restrições globais

- **Endereços:** os mesmos de hoje. `/`, `/links`, `/manifesto`, `/cultura`, `/cultura/<obra>`, `/newsletter/memoria-operaria`, `/newsletter/memoria-operaria/<n>`, `/<n>`, `/rss.xml`, todos também em `/es/...`. Novos: `/noticias`, `/noticias/<slug>` (e `/es/...`).
- **Estados:** `rascunho`, `em_revisao`, `publicada`, `rejeitada`. Papéis: `editor`, `revisor`, `redator`.
- **Travas:** iguais às de hoje (`validarPublicavel`, `validarObra`), com a manchete limitada a `MAX_PALAVRAS_MANCHETE = 8` e os marcadores `|` e `*` ignorados.
  - **newsletter:** fonte primária, checagem, foto com crédito e licença, manchete ≤ 8.
  - **noticia:** pelo menos 1 fonte, checagem, manchete ≤ 8, foto (se houver) com crédito e licença.
  - **cultura:** capa (se houver) com crédito e licença.
  - **pagina:** nenhuma.
- **Escrita:** toda política de escrita exige `auth.jwt()->>'aal' = 'aal2'`.
- **Segredos:** `service_role` nunca entra no Vercel nem no navegador.
- **Tradução:** modelo `claude-sonnet-5-5` numa constante `MODELO_TRADUCAO`, via Message Batches. As instruções são as de hoje (`scripts/traduzir.ts`), e o teto é de R$ 50/mês.
- **Dependências novas permitidas:** `@astrojs/vercel`, `@supabase/supabase-js`, `@supabase/ssr` e `supabase` (CLI, dev). `@anthropic-ai/sdk` passa para `dependencies`. Nenhuma outra.
- **Commits:** Conventional Commits em pt-BR, terminando com `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- **Paradas obrigatórias:** criar o projeto Supabase remoto, gravar segredos no Vercel/GitHub, criar a conta do fundador e fazer o deploy de produção. Cada uma é uma ação externa e só acontece com o ok do fundador no chat.

## Decisões tomadas sobre a spec (rulings)

1. **O idioma continua no `middleware.ts` da raiz** (Vercel Routing Middleware), e não vai para o middleware do Astro como a spec dizia.
   - **Por quê:** com as páginas no cache da borda, o middleware do Astro só roda quando o cache falha. O redirecionamento por idioma pararia de funcionar, porque o cache serviria a mesma página para todos. O middleware da raiz roda antes do cache.
   - **Custo se estiver errado:** nenhum. É o comportamento de hoje.
2. **Sem limitador próprio por IP no login.** Num servidor serverless, a memória não é compartilhada entre execuções, então um limitador em memória não limita nada. No lugar dele vão os limites do Supabase Auth, apertados em `supabase/config.toml` e no painel do Supabase.
   - **Custo se estiver errado:** um limitador de verdade exigiria uma tabela de tentativas, o que é uma tarefa extra.
3. **`fontes` mantém o formato atual** `{titulo, instituicao, url, tipo: 'primaria'|'secundaria', acessadaEm}`, e não `{nome, url}` como a spec dizia. `checagem` é `{por, em}`. As regras atuais dependem de `tipo`.
4. **`traducoes` ganha duas colunas que a spec não listava:**
   - `estado`: `pendente`, `pronta` ou `erro`;
   - `lote_id`: o id do lote na API.

   Elas existem para o recolhimento em lote.
5. **O backup diário usa a chave `anon`, não a `service_role`.** Ela só enxerga o que está publicado, que é exatamente o que vai para o arquivo.
6. **`/es/<peça sem tradução>`** mostra o texto em português com o aviso "Traducción en camino". As listas em espanhol mostram só as peças traduzidas, como hoje.

## Foco de revisão

1. **Peça publicada editada para ficar inválida** (apagar a checagem, trocar a manchete por uma de 9 palavras): o banco recusa, e a versão no ar continua a mesma. → Tarefa 1.
2. **Rascunho aberto pela URL pública direta:** 404, nunca o texto. → Tarefa 5.
3. **Corpo com `<script>` ou `<img onerror>`:** sai como texto inofensivo, não executa. → Tarefa 3.
4. **Número repetido** (duas edições Nº 004 na mesma série): o painel mostra "Já existe a edição Nº 004", e não um erro cru do banco. → Tarefa 7.
5. **Sessão que expira no meio da edição:** o texto não se perde. Ele fica no aparelho, e depois do login o editor volta para a mesma peça. → Tarefa 7.
