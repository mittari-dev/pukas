# Agenda editorial: plano de implementação

> **Para quem executa:** use superpowers:executing-plans (nativo) ou superpowers:subagent-driven-development, tarefa por tarefa. Os passos têm caixas (`- [ ]`) para acompanhar.

**Objetivo:** a seção AGENDA do painel. Ela mostra itens por dia e o espaço do ritmo da casa (editável), no celular só a semana e no computador semana e mês. O item pode ser ligado a uma peça e tem o botão "Começar a escrever".

**Arquitetura:**
- Duas tabelas novas com RLS: `agenda` e `ritmo`.
- Funções puras em `src/lib/agenda.ts`: datas, situação e espaços do ritmo.
- Acesso ao banco em `src/lib/banco/agenda.ts`, com o cliente da sessão, como o resto do painel.
- Duas páginas SSR (`/painel/agenda` e `/painel/agenda/ritmo`).
- O modal do item segue o padrão `<dialog>` do Estúdio, com o script em `public/agenda.js` (por causa da CSP).

**Stack:** Astro 7 SSR, Supabase (Postgres + RLS), Vitest, CI no GitHub Actions (banco e e2e).

**Spec:** `docs/specs/2026-11-07-agenda-design.md`

## Regras globais

- Toda escrita exige 2FA (aal2): `privado.com_2fa()` e `privado.papel_atual()` nas políticas.
- Script do painel só em `public/*.js`, nunca embutido no HTML (o `src/lib/painel/csp.test.ts` vigia as páginas em `src/pages/painel`).
- Fuso: `America/Sao_Paulo`. Semana de segunda a domingo. Datas como `YYYY-MM-DD`.
- Os tipos da agenda são `newsletter`, `noticia` e `cultura` (sem `pagina`). A série vem de `SERIES`, em `src/lib/formato.ts`.
- Visual: fios finos, chapéu vermelho, sem sombra nem canto arredondado. Espaços só com os tokens `--esp-*`.
- Os testes de banco e e2e rodam só no CI. Localmente rodam `npm test` e `npm run check`.

## Pontos de atenção na revisão

1. **Virada de ano na semana:** uma semana que começa em 29/12 e termina em 04/01 mostra os 7 dias certos (teste em `semanaDe`).
2. **Domingo à noite em São Paulo** já é segunda em UTC, mas "hoje" tem de ser o domingo (teste em `hojeEmSaoPaulo`).
3. **Uma peça ligada a dois itens:** o banco recusa (índice único). O painel mostra "Esta peça já está ligada a outro item." em vez de um erro cru.
4. **Peça ligada apagada:** o item continua, `peca_id` vira null e a situação volta a ser a manual (`on delete set null`, mais o teste em `situacaoDoItem` com peça ausente).
5. **Ritmo pausado ou de outra série:** não gera espaço nem some com um item de outra série (teste em `espacosDoRitmo`).

**Interfaces:**
- **Produz:**

  - a tabela `agenda`: `id` uuid pk, `dia` date not null, `tipo` tipo_peca not null check (tipo <> 'pagina'), `serie` text, check (tipo <> 'newsletter' or serie is not null), `titulo` text not null check (char_length(trim(titulo)) between 1 and 120), `nota` text, `situacao` situacao_agenda not null default 'ideia', `peca_id` uuid unique references pecas on delete set null, `responsavel` uuid references perfis on delete set null, `criado_por` uuid default auth.uid() references auth.users on delete set null, `criado_em` timestamptz default now();
  - a tabela `ritmo`: `id` uuid pk, `dia_semana` smallint not null check (between 1 and 7), `tipo` tipo_peca not null check (tipo <> 'pagina'), `serie` text, `rotulo` text, `ativo` boolean not null default true, `criado_em` timestamptz default now();

Sem JavaScript, `:target` mostra o formulário na página, como no Estúdio.
